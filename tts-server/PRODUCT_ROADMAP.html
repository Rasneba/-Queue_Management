3. Data dictionary

Schema source of truth: schema.sql (idempotent, applied by migrate.py). All tables use BIGSERIAL id primary keys and TIMESTAMPTZ created_at.

users — one row per registered account

ColumnType & constraintsMeaning
idBIGSERIAL PKInternal user id; referenced by all child tables.
emailTEXT UNIQUE NOT NULLLogin identity. Uniqueness enforced in DB (409 on conflict).
nameTEXT NOT NULL DEFAULT ''Display name shown in the dashboard greeting.
password_hashTEXT NOT NULLPBKDF2-HMAC-SHA256, 210,000 iterations, per-user salt. Plaintext never stored.
credits_balanceBIGINT DEFAULT 10000, CHECK ≥ 0 Cached spendable balance; the credit_ledger is the audit trail. Starts at 10,000 on signup.
is_activeBOOLEAN DEFAULT TRUEReserved for suspension. Not yet enforced in middleware.
created_at / updated_atTIMESTAMPTZ DEFAULT now()Lifecycle timestamps.

sessions — login tokens (opaque, hashed)

ColumnType & constraintsMeaning
user_idBIGINT FK → users, ON DELETE CASCADEOwner. Indexed.
token_hashTEXT UNIQUE NOT NULLSHA-256 of the bearer token. The raw token is shown once and never stored.
expires_atTIMESTAMPTZ NOT NULLExpiry (30 days). Indexed for sweeping.
revoked_atTIMESTAMPTZ NULLSet by logout; NULL = live.

api_keys — developer keys (hashed, revocable)

ColumnType & constraintsMeaning
user_idBIGINT FK → users, CASCADEOwner. Indexed.
nameTEXT DEFAULT 'default'User label shown in the dashboard.
key_prefixTEXT NOT NULLFirst characters shown masked in the UI (e.g. sk_live_ab12…).
key_hashTEXT UNIQUE NOT NULLSHA-256 of the secret. Secret shown once at creation via X-Api-Key or Bearer.
scopesTEXT DEFAULT 'tts'Reserved. Not enforced yet — all keys have full TTS scope.
last_used_at / revoked_atTIMESTAMPTZ NULLUsage tracking and soft revocation.

credit_ledger — append-only money trail

ColumnType & constraintsMeaning
user_idBIGINT FK → users, CASCADEOwner. Indexed on (user, created DESC).
deltaBIGINT NOT NULLSigned change: negative = spend, positive = grant. Never zero in practice.
reasonTEXT NOT NULLMachine reason. Observed values: signup (+10000), speak (−chars).
balance_afterBIGINT NOT NULLBalance snapshot after applying delta. Reconciles with users.credits_balance.

usage_events — aggregate-friendly counters

ColumnType & constraintsMeaning
user_idBIGINT FK → users, CASCADEOwner. Indexed on (user, created DESC).
kindTEXT DEFAULT 'speak'Event type. Only speak is written today; reserved for normalize, queue.
characters / creditsINTEGER DEFAULT 0Input length and cost charged. Powers GET /usage totals and daily series.

tts_requests — per-generation history (user-visible)

ColumnType & constraintsMeaning
user_idBIGINT FK → users, ON DELETE SET NULLNULL = anonymous or deleted-user row. Survives account deletion for aggregate stats.
request_idTEXT NULLClient-supplied idempotency key (X-Request-Id). Rarely set; enforce uniqueness per user when idempotency ships.
input_text / spoken_textTEXTRaw input and post-normalization text the engine actually voiced.
lang / voice / gender / age / styleTEXTVoice selection as requested (e.g. am, am-ET-MekdesNeural, female, adult, professional).
audio_formatTEXT DEFAULT 'mp3'mp3 | wav | flac.
characters / credits / audio_bytesINTEGER DEFAULT 0Billing inputs and output size shown in History.
duration_ms / warningsINTEGER / TEXT, nullableReserved: engine-reported duration and normalization warnings. Currently NULL.
Relationships at a glance: users 1→N sessions, api_keys, credit_ledger, usage_events; users 1→N tts_requests with SET NULL. Deletes cascade everywhere except history, which is intentionally retained.

4. Credit & metering rules

  • Unit: 1 character = 1 credit (CREDITS_PER_CHARACTER = 1).
  • Signup grant: +10,000 (reason = 'signup').
  • Charge point: inside record_usage() on every /speak — including cache hits (fixed: previously repeats were free and unlogged).
  • Insufficient balance: account.charge() raises ValueError, surfaced as HTTP 402. Other DB failures are best-effort (audio still served) — a deliberate demo tradeoff.
  • Anonymous callers are never billed and never written to the DB (abuse guard).
  • Frontend display: header badge updates in place after generation; History re-renders from GET /history; logged-out viewers see clearly-separated demo placeholders.

6. Improvement backlog (prioritized)

P0 — before charging real money

  • Chapa + Telebirr billing: verify payments server-side, credit packs on webhook, invoice rows. Frontend billing page already expects this.
  • Rate limiting: per API key + per IP on /speak (e.g. slowapi or nginx-level), 429 responses the UI already handles generically.
  • Auth hardening: set a real SESSION_SECRET, enforce is_active (D10), enforce key scopes (D8), rotate any exposed Neon credential to a least-privilege role.
  • Password reset + email verification: token table + mailer; replaces the /forgot-password placeholder.

P1 — product depth

  • Stored audio + history playback: object storage (R2/S3), tts_requests.audio_url, wire history-play to the real file (D7).
  • Lexicon in Postgres: new lexicon_entries(user_id, word, pronunciation, …) table, per-user overrides, UI management (D4).
  • Admin backend: replace frontend-only admin scaffold with real user/payment/usage queries + audit log table.
  • Usage alerts & plan enforcement: monthly quotas, 80%-used notifications, upgrade prompts driven by real /usage.
  • Batch generation UI: expose /queue-speak in the studio with progress + combined download.
  • Idempotent retries: unique (user_id, request_id) (D9) so mobile retries never double-charge.

P2 — growth & ops

  • Own Amharic voice model: licensed voice data → train/fine-tune VITS → swap behind the same /speak contract. Full plan in AMHARIC_TTS_DESIGN.html §4.
  • More voices & languages: additional Edge voices, Oromo/English parity in the studio presets.
  • Observability: structured logs, error tracking, uptime checks on /health + /db/health, Neon branching for staging.
  • CI guardrails: run render_check.mjs on every PR so a blank-page regression can never ship again.
  • Fill telemetry gaps: duration_ms, warnings (D11), last_used_at updates.
  • Dark mode (optional): only if cheap — light remains the default product theme.

7. How to add a feature (conventions)

  • New endpoint: add to server.py (public/TTS) or account_routes.py (authed). Reuse current_user() for auth; return 402 via ValueError from account.charge().
  • New table: append CREATE TABLE IF NOT EXISTS to schema.sql, add accessors in the matching module, index (user_id, created_at DESC).
  • New UI: vanilla JS in frontend/app.js (route + renderer + attachEvents wiring), styles in frontend/styles.css using existing variables. No bundler: no import of CSS, no import.meta.env — runtime config comes from window.__NEB_CONFIG__.
  • Build output contract: dist/index.html + dist/assets/{app.js, styles.css, config.js}. Never reference files outside /assets/.
  • Secrets: server-side only. Anything starting VITE_ ships to browsers.

8. Verification checklist

# syntax + static build
node --check frontend/app.js
npm run build
# preview-mode render, all routes, zero script errors
node render_check.mjs dist
# full flow vs local API: register → speak → credits → history
python server.py &
node render_live.mjs dist http://127.0.0.1:8765
# billing semantics incl. cache hits (must print PASS)
python test_metering.py http://127.0.0.1:8765
# account regressions + cleanup test rows afterwards
python test_accounts.py && python cleanup_tests.py
# live deployment check (rendering only, no test data)
node render_url.mjs https://nebaamharictts.vercel.app/
Rule of thumb: if render_check.mjs fails, do not deploy — it is the blank-page guard. If test_metering.py fails, do not deploy — billing is wrong.
